# HW Be Careful

## Rule

- The folder name should be `HW{num}_{student_id}`. It must be compressed into a zip file (e.g., `HW4_115356048.zip`).
- When submitting, include all .java files.
- A Main.java file must be included.
- **The output format must match the example exactly**.
- When there is a formatting error, there is no room for argument.

## Deadline

Assignments are usually released at 00:00 on Wednesday.

- The first submission is due by 11:59 on Sunday.
- The second submission is due by 23:59 on Monday.

Each assignment allows two submission attempts. Questions and testing are permitted during TA sessions that fall within the submission period. After the second submission deadline, no additional requests will be processed.

## Bonus

- Please rename your bonus file to `HW{num}_{student_id}_bonus`. For example: `HW4_115356048_bonus`.
- Include a `bonus.txt`or a `bonus.md` file that describes each bonus item separately and gives the file name and line number where it was implemented.
- If your bonus includes interaction with an AI tool, record each prompt in a separate paragraph. Include the AI tool name, the purpose of the prompt, and a brief description of how you used or modified the result.
- You are responsible for understanding and checking any code or explanation generated by an AI tool.
- (Optional) You may also add comments in the code.

### If you encounter a conflict while downloading HW

First, check the current status of your local repository:

```bash
git status
```

If `git status` shows `unmerged paths`, an earlier update is still unfinished. If you have files to keep, copy them to another folder outside `2026Fall-DS` first. Then run the commands in case 2 to clean up the repository, and copy your files back afterward.

#### 1. If you have local files to keep

Temporarily save your local changes, update the files, and restore your changes.

You do not need to run `git add` before `git stash`. The `-u` option also saves untracked files:

```bash
git stash push -u -m "save local homework files"
```

Download the latest HW files:

```bash
git pull --ff-only origin main
```

Restore your local files:

```bash
git stash pop
```

Finally, check the status again:

```bash
git status
```

If `git stash pop` reports a conflict, open the reported files, remove the conflict markers (`<<<<<<<`, `=======`, and `>>>>>>>`), and keep the correct content. After fixing each file, run:

```bash
git add <file-name>
```

You only need `git add` after manually fixing a conflict. You do not need to run `git commit` just to download the HW files.

#### 2. If you do not have local files to keep

Make sure you do not need any local changes before running these commands. They update all tracked files to exactly match the remote repository:

```bash
git fetch origin
git reset --hard origin/main
```

Check that the update is complete:

```bash
git status
```

The `git reset --hard` command discards local changes to tracked files. It normally leaves untracked and ignored files untouched. However, a file or folder may be overwritten or removed if it is in the way of checking out a tracked file. Do not use `git clean -fdx`, because it deletes ignored and untracked files.
